## 1. 最终交付物

**一句话**：一个自包含的公开 git 仓库 —— 评审 clone 后按 README 的命令可直接复现全部 5 个验收场景，仓库内同时具备「可运行代码 + 可执行测试 + 真实运行证据 + 五份文档」四件套。

| # | 交付物 | 硬性内容 |
|---|---|---|
| 1 | **可运行项目** | `src/`（Agent 主体 + 模型接入 + 三个工具：素材检索、时长估算、规则检查） |
| 2 | **运行入口** | CLI / HTTP API / Notebook **三选一**，README 给出可复制的完整命令 |
| 3 | **测试** | `tests/` 可执行测试 |
| 4 | **证据** | `examples/` ≥3 组「输入 + 实际输出 + Trace」，并覆盖全部验收点 |
| 5 | **合成资料** | `data/` 素材库与品牌规则（本题为自造数据） |
| 6 | **文档** | `docs/01-requirements.md`、`02-solution.md`、`03-evaluation.md`、`04-ai-usage.md`、`05-retrospective.md` |
| 7 | **工程配套** | `README.md`、依赖文件、`.env.example`（无变量须注明"无需配置"） |
| 8 | **离线兜底** | 模型不可用时的 Mock 入口，并**写明 Mock 的能力边界** |
| 9 | **提交信息** | 题号 + GitHub URL + **最终 commit SHA**；私有仓库须给指定评审账号读权限 |

**Agent 本身必须产出的结果字段**（缺一不可）：
标题、分镜、旁白/字幕、预计总时长、素材来源 ID、风险、任务状态。

## 2. 硬约束

### A. 决策机制（最高优先级，不满足即不达标）

| 约束 | 原文要求 |
|---|---|
| A1 | 至少实现 **1 个真实循环**：模型选动作 → 执行工具 → 观察结果 → 模型调整下一步或结束 |
| A2 | **明确排除**：仅固定条件分支、自动重试、预设决策日志 —— 三者任一单独存在均"不视为完成" |
| A3 | ≥**2 条**执行路径的运行记录，须体现"因工具结果不同而改变动作" |
| A4 | 每条记录须含：步骤、工具参数、返回摘要、后续动作、**简要决策依据**（不提交模型思维过程） |
| A5 | 必须设**步数或工具调用次数上限**；达上限返回**明确的未完成状态**，不得静默截断 |

### B. 业务规则（题目四特有）

| 约束 | 内容 |
|---|---|
| B1 | 输入维度：主题、受众、平台、目标时长、风格；产品素材与品牌规则 |
| B2 | 检索无结果时：由模型决定**改写查询**或**请求补充**（二选一，须有判断） |
| B3 | 时长/规则检查不通过时：**调整脚本并再次检查**，或**明确说明无法满足** |
| B4 | 事实可追溯：产品事实只能来自素材 ID；无效果数据时**禁止**出现"效率提升 80%"类结论 |
| B5 | 编造产品事实 = **关键缺陷**（直接否决级） |
| B6 | 审核方式：将**素材 ID、分镜时长、检查结果逐一对应**；改动时长或检索结果，须能观察到下一步动作随之变化 |

### C. 证据约束

| 约束 | 内容 |
|---|---|
| C1 | ≥3 组「输入 + 实际输出 + 运行记录」 |
| C2 | 必须覆盖 5 个场景：正常生成 / 缺关键信息 / 无素材 / 工具失败 / 超时长修正或明确失败 |
| C3 | 同时覆盖所选题的**全部验收点**（允许一个用例覆盖多点） |
| C4 | Trace 与测试结果存放 `examples/`，且 `03-evaluation.md` 须**引用具体文件** |
| C5 | 截图、视频**不能替代**代码与运行记录 |

### D. 工程与提交

| 约束 | 内容 |
|---|---|
| D1 | 语言、模型、框架自选；框架名不加分，**能解释取舍与修改结果**才加分 |
| D2 | 用框架须注明版本、用到的功能、承担的职责 |
| D3 | 不提交真实密钥、隐私数据 |
| D4 | 全部材料置于**同一仓库** |
| D5 | 界面、线上部署、多 Agent、生产级 Runtime **均非必需** |

### E. 时间

| 约束 | 内容 |
|---|---|
| E1 | 建议投入 **3 小时**，优先核心链路 |
| E2 | 须**记录实际用时**与**未完成部分** |

## 3. 隐含要求（我的推断，非材料原文）

> 以下均为「材料没写、但不做就会被扣分或质疑」的项，逐条标注了推断依据。

| # | 隐含要求 | 推断理由 |
|---|---|---|
| I1 | **时长估算必须确定性可复算**（如字数/语速公式），不能由模型"估" | 否则 `38s→28s` 无法被评审复核，修正闭环变成表演 |
| I2 | **脚本须结构化输出**（分镜为条目/JSON），而非一整段文本 | "可编辑"是用户目标原文 |
| I3 | **素材 ID 要绑到分镜级**，不能只在文末列来源清单 | 审核要"逐一对应" |
| I4 | **三种失败态必须互相区分**：检索空 / 工具抛错 / 时长不达标 —— 处置不同 | 题目把三者列为独立验收项 |
| I5 | **缺信息不得静默假设**：走"请求补充"分支，或显式标注假设并降级任务状态 | "不得偷偷假设"在项目里的镜像 |
| I6 | **Trace 必须是运行时落盘产物**，不能事后手写 | 手写 trace 一被要求现场重跑即穿帮 |
| I7 | **Mock 与真实模型走同一代码路径**，仅替换模型调用 | 否则"Mock 只验证流程"这句话自己就不成立 |
| I8 | **品牌规则须可枚举**（禁用词 / 必提信息 / 平台时长上限），输出 pass-fail 清单 | 规则检查工具需可测试 |
| I9 | `05-retrospective.md` 要写**真实难点**，`04-ai-usage.md` 要写**个人改了什么、怎么验证** | 考核目标是"观察主动学习与改进能力" |
| I10 | 参考仓库 `lwz1357/agent-campus-submission-example` **明确声明未实现真实 ReAct、不作达标依据**，只能借目录结构，不能当答案 | 需知第 48 行 |

## 4. 什么叫完成

分两层。**最低完成线**是"不淘汰"，**高分线**是"拿分"。

### 4.1 最低完成线（8 条，全部可机械验证）

- [ ] 陌生环境 clone → 按 README 命令**一次跑通**，含**无需 API key** 的 Mock 路径
- [ ] 5 个验收场景各有 1 条可复现命令 + `examples/` 中对应产出
- [ ] Trace 中能明确指认 **≥2 处**「因为工具返回 X，所以下一步变成 Y」
- [ ] 超时长用例展示完整闭环：首稿超时 → 调整 → 重估 → 通过；或输出"无法满足"及具体原因
- [ ] 每个分镜的事实声明都能追到素材 ID，人工抽查**零编造**
- [ ] 有 1 条用例走到**调用上限**，返回"未完成"状态而非崩溃/空返回
- [ ] `pytest`（或等价）全绿，且断言的是**行为**（如"检索为空 → 触发改写或请求补充"），不是字符串快照
- [ ] 提交了三元信息：题号 + 仓库 URL + commit SHA，且链接在无痕窗口可打开

### 4.2 高分线（评审真正的区分点）

- [ ] 决策依据字段写的是**判断逻辑**（为什么改写查询而不是重试、为什么是压缩而不是删分镜），不是复述动作
- [ ] 同一条用例**改输入**（时长 30s→15s、或把素材删空）后，动作序列**真的变了** —— 这是 B6 的直接检验
- [ ] 修正前后两版脚本 + 两次估算结果**都留档**，能看出压缩策略（删哪个分镜、哪句旁白）
- [ ] `03-evaluation.md` 诚实记录失败用例与已知限制，而非只罗列成功
- [ ] 框架（若用）有版本号与"它替我省了什么、我改了什么"的说明

### 4.3 完成的前提：以下未定项须先定

`待确认` 见文末登记表；**在 D1/D2/D3 未定之前，"完成"的边界无法闭合**。

## 5. 最容易翻车的风险点

按「发生概率 × 致命程度」排序。

| 排名 | 风险 | 后果 | 早期信号 |
|---|---|---|---|
| **1** | **假 ReAct**：实际是 if/else 流水线，模型只负责写文案 | 直接不达标（A1/A2） | 代码里找不到"模型返回的 next_action 被解析并分发"的环节 |
| **2** | **时长数字与脚本不匹配**：估算工具与最终脚本脱节，或照抄示例的 38s/28s 但内容撑不起 | 修正闭环被判定为伪造 | 手工数一下字数/语速，算不出 28s |
| **3** | **压缩时引入幻觉**：为压时长"顺手"加了素材里没有的卖点 | 关键缺陷，B5 否决 | 脚本里出现素材库 grep 不到的名词 |
| **4** | **素材 ID 沦为装饰**：只在文末列 ID，分镜无映射 | 审核"逐一对应"无法完成 | trace 里没有分镜↔素材的关联字段 |
| **5** | **失败态混同**：无素材、工具挂、超时长都返回同一句"生成失败" | 3 个验收点塌缩成 1 个 | 错误信息文本雷同、无错误类型字段 |
| **6** | **Trace 事后手写** | 与真实运行不符，现场重跑即崩 | trace 里没有时间戳/调用序号/原始参数 |
| **7** | **环境不可复现**：硬编码绝对路径、依赖未冻结、主链路必须付费 key | 评审跑不起来 = 全盘归零 | README 命令在干净目录里失败 |
| **8** | **五份文档写成模板套话**（尤其 03/04/05 无真实失败、无真实用时） | 丢掉"学习与改进"的分 | 03 里没有任何一条失败记录 |
| **9** | **提交形式性失分**：漏 commit SHA / 私有仓库未授权 | 无法评审 | 链接匿名打不开 |
| **10** | **时间黑洞**：3h 预算花在 UI、框架选型、多 Agent 上 | 核心链路没做完 | 2 小时时还没有跑通一次完整循环 |

**额外结构性风险**：题目要求的 5 个场景 × 至少 3 组数据 × 2 条路径，证据量不算小。若先写代码后补 trace，很容易凑不齐 C2 要求 —— 证据应在设计阶段就作为一等公民规划。
