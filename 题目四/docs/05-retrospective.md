# 05 · 风险、限制与回顾

## 已知风险与限制

| # | 问题 | 影响 | 为什么当前可接受 | 什么时候必须修 |
|---|---|---|---|---|
| R1 | **语义级编造仍可能**：`fact_refs` 只保证"引用为真"，不保证"旁白没超出所引事实" | 可能交付"素材里没有的功能" | 需要另一个模型做裁判，成本超出预算；已用提示词约束 + 人工抽查兜底 | 上线给真实品牌方用之前 |
| R2 | 模型可能**绕过 `compress`** 手改旁白 | 修正退化为不可复现（旧行为约 1/6 收敛） | 提示词已明确禁止；实测 3/3 走工具 | 若采样发现绕过率不可忽略 |
| R3 | **欠时长不阻断**：30s 目标写 18s 也算通过 | 脚本可能偏短 | 题目只要求"不超时长"；加下限会引入新的误判 | 客户明确要求时长下限时 |
| R4 | 压缩**内容底线 50%** 是经验值 | 阈值过低会压没内容，过高会过早判失败 | 当前取决于"删一半还剩多少信息"，没有客观标准 | 有真实反馈数据后标定 |
| R5 | `03` 有**两种失败态**（`UNSATISFIABLE` 或 `needs_input`） | 同一输入可能得到不同的"失败" | 两者都是 4 步内收敛的显式失败，符合"明确失败" | 若要求失败态唯一 |
| R6 | `examples/` 是**运行快照**，不是确定性重放 | 换时间重跑，正常场景的文案会变 | 场景契约测试仍能校验结构；`02` 已做到 3 次完全一致 | 需要可复现演示时 |
| R7 | 真实模型**不在自动化测试里** | 无法防住模型行为漂移 | 需要带 key 的 CI，3 小时预算内不划算 | 进入持续迭代后 |
| R8 | `platform` 未知时**静默降级**为 generic | 用户写错平台名不会报错 | generic 参数合理，不影响正确性 | 平台参数差异变大时 |
| R9 | 同一输入**并发跑会互相覆盖** trace | 证据丢失 | 无并发使用场景 | 接入服务化时 |
| R10 | `--out` 可指向任意目录 | 可写工作区外路径 | 本地 CLI，写权限本就属于用户 | 服务化部署时 |
| R11 | 仅在 **Windows + Python 3.9** 验证 | 其他环境可能有编码/路径问题 | 已用 `utf-8-sig` 兼容 BOM；只用标准库 | 交付前在目标环境跑一遍 |
| R12 | 未统计**成本与耗时** | 无法估算批量运行开销 | 单次 6–11 步，量级很小 | 批量接入时 |

## 最难的三件事

**1. 分清"真循环"和"假流程"**
最省事的写法是"检索 → 估时长 → 检查 → 输出"的固定顺序，模型只在分叉处答选择题。
它能过功能测试，但撞在"固定条件分支不算完成"的红线上。
最后的做法是：**限定动作空间，而不是限定顺序**——模型自由选动作，但只能从 8 个里选。

**2. 观察写得不可行动（犯了三次）**
一开始工具只回"未通过"。模型于是反复检索、反复删两个字，永远收敛不了。
后来才明白：**ReAct 的瓶颈不在循环结构，在观察里有多少可用信息**。
`search` 要回传事实正文，`check_rules` 要说清哪条错、正确的是什么，`estimate` 要给"还差多少字"。

**3. 让证据可复现**
第一版让模型自由压缩，同一输入 6 次只有 1 次成功。
把算术从模型手里拿走、交给确定性工具后，3 次全部收敛到同一个结果。
**"模型做判断、工具做算术"** 是这次最值钱的一条经验。

## 学习收获

- 评审看的是**证据链**，不是功能清单；能跑不等于能证明。
- 崩溃容易发现，**静默失真**才致命（素材 ID 被拆成字符、分镜 id 重复导致时长对不上、Mock 冒充真模型）。
- 自己加的约束可能比题目本身更伤——"不低于目标 80%"这条是我加的，结果把系统跑崩了。
