# 02 · 设计

## 一句话

一个**限定动作空间的显式 ReAct 循环**：模型每轮只能从 8 个动作里选一个，系统执行确定性工具，把结果回灌，由模型决定下一步或结束。

## 为什么不用 Agent 框架

题目明确"框架名称不加分，能解释取舍才有价值"。选择手写循环的理由：

1. **合规风险最低**。评审的否决项是"固定条件分支的假 Agent"。循环摆在自己代码里，读 30 行就能确认，不需要解释框架行为。
2. **trace 归自己管**。框架的 step/event 结构未必含"决策依据"，二次抽取既麻烦又脆弱。
3. **环境风险最低**。零第三方依赖，评审 clone 下来就能跑；3 小时预算里"能跑通"比"架构漂亮"重要。

代价：需要自己写护栏、重试、终止逻辑（约 900 行）。这部分是本项目的主要工作量。

## 核心结构

```
CLI → Loop ──→ ModelClient.decide()      模型只提议动作
         ├──→ Policy.validate()          护栏：白名单 / 前置条件 / 上限 / 重复
         ├──→ Dispatcher.dispatch()      动作 → 工具
         ├──→ Tools                      search / duration / rules / compress
         └──→ TraceWriter                每步落盘（脱敏）
```

**隔离铁律**：模型不能调工具、不能改状态、不能写文件；工具不知道模型存在。

## 8 个动作

| 动作 | 作用 |
|---|---|
| `search` | 按关键词或素材 ID 检索 |
| `rewrite_query` | 检索为空时换关键词重试 |
| `ask_clarify` | 素材不足时请求补充，转 `needs_input` 终态 |
| `compose` | 提交/修改脚本草案（含分镜、旁白、素材与事实引用） |
| `estimate` | 按旁白字数估算时长 |
| `compress` | **确定性压缩**到目标时长内 |
| `check_rules` | 品牌规则检查 |
| `finish` | 结束并交付 |

## 三个关键设计决定

### 1）时长只由工具给，模型不许自报

`Shot.duration_s` 是工具写入字段。模型给的秒数一律丢弃，时长 = 字数 ÷ 平台语速，逐镜四舍五入后求和。
**原因**：如果允许模型自报，"38 秒 → 28 秒"就无法被复算，修正闭环变成表演。

### 2）事实必须引用素材原文

每个分镜带 `fact_refs: [{material_id, fact}]`，`fact` 必须**逐字等于**该素材 `facts` 里的某一项。
规则工具检查四类问题：未绑素材、未引用事实、引用了不存在的事实、引用不属于该分镜的素材。

**局限**：它能证明"引用是真的"，不能证明"旁白没超出所引事实"。后者需要语义核验，本项目未做（见 05）。

### 3）压缩必须确定，否则不可复现

第一版让模型自由改写旁白来压时长。实测同一输入 6 次只有 1 次收敛，其余落到 `UNSATISFIABLE`。
改为工具 `compress`：模型只决定**何时压**，裁剪算术全部由工具完成（逐字削减 + 标点回退 + 内容底线 50%）。
同一场景从 1/6 变为 **3/3**，且每次都收敛到 7.0s / 7 步。

## 观察必须可行动

这是踩了三次坑才立下的规矩：

- `search` 必须回传 facts 正文，否则模型看不到可用事实，只能反复检索；
- `check_rules` 必须说清"哪条错、该素材可用的正确事实是什么"；
- `estimate` 必须给出"还差多少字"，否则模型每次只删两个字符。

**结论：ReAct 的瓶颈不在循环，在观察的信息量。**

## 护栏

| 护栏 | 规则 |
|---|---|
| 白名单 | 只接受 8 个动作 |
| 前置条件 | `finish` 前必须 `estimate` 与 `check_rules` 均通过；两者前必须有草案；未给素材 ID 时必须先检索 |
| 三重上限 | 步数 16（可调到 100）、工具调用 18、同一动作同参数最多 2 次 |
| 修正上限 | 超时长最多修正 3 次，之后必须明确失败 |
| 结构校验 | 分镜 id 唯一、旁白非空、分镜 ≤ 20、旁白总字数 ≤ 4000 |

## 终止态

`completed` / `incomplete` / `needs_input` / `failed`，每种都带 `reason` 和错误码，不存在"跑完但没有结论"。

## 已知取舍

| 取舍 | 为什么不选另一边 |
|---|---|
| 单一职责的线性循环，不做多 Agent | 需知明确说多 Agent 非必需、不加分 |
| 素材库用合成数据 | 题目未提供真实素材，且要避免隐私 |
| CLI 而非 HTTP/界面 | 三选一里最容易复现的那个 |
| 不做语义级事实核验 | 需要另一个模型做裁判，超出 3 小时预算 |
