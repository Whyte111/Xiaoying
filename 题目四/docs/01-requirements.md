# 01 · 需求

## 用户

短视频创作者，尤其是**一个人做号**、没有专门文案/剪辑支持的人。

## 目标

给定主题、受众、平台、目标时长、风格，产出一份**可直接开拍**的脚本，且：

1. 所有产品表述都能追溯到素材原文；
2. 总时长在目标内，且**可复算**；
3. 信息不足时明确说"不够"，而不是编。

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| `topic` | 是 | 主题 |
| `platform` | 是 | 平台，决定语速与时长上限 |
| `target_duration_s` | 是 | 目标秒数，> 0 且 ≤ 600 |
| `audience` / `style` | 否 | 影响文案风格 |
| `material_ids` | 否 | 指定素材；为空时由 Agent 自行检索 |

## 交付结果（每次运行必须产出）

标题、分镜、旁白/字幕、预计总时长、素材来源 ID、风险、任务状态。

## 范围

**做**：一条完整的"模型决策 → 工具执行 → 观察回灌 → 再决策"闭环；5 类验收场景；离线 Mock；逐步骤 trace。

**不做**：图形界面、线上部署、多 Agent、生产级运行时、真实素材抓取、视频合成。

## 成功标准

1. 6 个场景（正常 / 缺信息 / 无素材 / 工具失败 / 超时长修正 / 超时长失败）都能跑出并留下 trace；
2. 每个分镜的事实都能对应到素材原文，无编造；
3. 分镜时长之和等于总时长，且能用字数反推；
4. 达到步数/工具调用上限时返回明确的未完成状态，不静默截断；
5. 全部自动化测试通过。

## 明确不承诺

- 不承诺脚本"好看"或"能涨粉"——只承诺事实可追溯、时长可复算；
- 不承诺真实模型每次都收敛（见 `05-retrospective.md`）。
