# 系统骨架 · 题目四：短视频脚本 Agent

> 结构文档，不含实现代码。
> 上游依据：[问题定义.md](./问题定义.md)、[方案对比.md](./方案对比.md)
> 选定形态：方案 A —— 手写显式 ReAct 单循环，无框架，限定动作空间。
> 技术前提（已确认）：Python / CLI / 真实 DeepSeek + 离线 Mock / 自造合成数据 / 默认「通用短视频 30s」。

---

## 0. 已锁定的边界决策

| # | 决策 | 结论 |
|---|---|---|
| B1 | `rewrite_query` 与 `ask_clarify` 的语义 | **拆为两个动作**：`rewrite_query` 继续循环重搜；`ask_clarify` 转 `needs_input` 终态 |
| B2 | 分镜时长由谁定 | **由 `tools.duration` 按旁白字数反算**，模型只提供内容，不提供秒数 |
| B3 | 超时长允许修正次数 | **最多 2 次**；第三次仍超标 → `UNSATISFIABLE` |
| B4 | 是否强制先检索 | `material_ids` 为空时**强制先 `search`**，否则 `finish` 被 policy 驳回 |
| B5 | 语速参数 | 平台配置表，默认 **4.5 字/秒**（中文旁白），数值自定，可配置 |
| B6 | 规则文件缺失 | **fail-closed**：报 `TOOL_ERROR`，不视作“空规则” |
| B7 | 必填字段集合 | `topic` / `platform` / `target_duration_s` 三项必填 |

> 这些决策全部偏向“可复算 + 可判定”，目的是让 5 个验收场景能被机械触发，而不是靠运气。

## 1. 模块区分

统一分层，依赖方向单向：`cli → agent → (llm, tools) → domain`。

| 模块 | 路径 | 层级 |
|---|---|---|
| 入口 | `src/cli.py` | 入口 |
| 循环控制器 | `src/agent/loop.py` | 决策 |
| 动作分发器 | `src/agent/dispatcher.py` | 决策 |
| 策略护栏 | `src/agent/policy.py` | 决策 |
| 提示词 | `src/agent/prompts.py` | 决策 |
| 模型客户端 | `src/llm/{base,deepseek_client,mock_client}.py` | 适配 |
| 工具 | `src/tools/{search,duration,rules}.py` | 工具 |
| 领域模型 | `src/domain/{schemas,errors}.py` | 贯穿 |
| Trace 写入 | `src/observability/trace.py` | 贯穿 |
| 数据与配置 | `data/{materials,brand_rules,platforms}.json` | 配置 |
| 场景运行器 | `scripts/run_scenarios.py` | 入口 |
| 测试 | `tests/{unit,loop,e2e}/` | 验证 |

**隔离铁律**：`tools` 不知道 `llm` 的存在；`llm` 不知道 `tools` 的存在。

## 2. 目标结果

每次运行必须收敛到三种终态之一，**不允许停留在中间状态**。

| 编号 | 终态 | 必须满足 | 支撑的验收场景 |
|---|---|---|---|
| **G1** | `completed` | 标题 + 分镜 + 旁白/字幕 + 总时长 + 素材来源 ID + 风险；每个事实声明可回溯到素材 ID；总时长与工具复算一致；规则检查 pass | 正常生成 |
| **G2** | `incomplete` / `needs_input` / `failed` | 必带 `reason` + 已完成部分；不得返回空对象或异常堆栈 | 缺信息 / 无素材 / 工具失败 / 超时长失败 |
| **G3** | 证据 | 每次运行必然落一份 trace 文件，内容为运行时产物 | A3 / A4 的路径证据 |

## 3. 各模块职责

| 模块 | 职责 | 明确不做 |
|---|---|---|
| `cli` | 解析参数、加载输入、调用循环、打印摘要、返回退出码 | 不做任何决策 |
| `loop` | 持有 `LoopState`；驱动 `decide → policy → dispatch → observe`；判定终止 | 不直接调工具、不解析业务规则 |
| `dispatcher` | 动作名 → 工具函数映射；`ToolResult` → observation | 不校验语义合法性 |
| `policy` | 动作白名单、前置条件、步数/调用上限、重复动作检测 | 不生成内容、不评价脚本质量 |
| `prompts` | 系统提示词、observation 格式化 | 不含密钥、不含业务数据 |
| `llm` | `decide(state, observations) -> ActionDecision` | 不执行工具、不写文件、不改 state |
| `tools.search` | 按关键词或素材 ID 检索 `data/materials.json` | 不生成文案、不联网 |
| `tools.duration` | 按旁白字数 × 语速换算分镜与总时长 | 不判断内容好坏 |
| `tools.rules` | 执行可枚举规则（禁用词 / 必提项 / 时长上限 / 平台限制） | 不做主观评审 |
| `domain` | 数据类 + 错误码枚举 | 无业务分支 |
| `trace` | 追加写 `TraceEvent`，脱敏 | 不记录密钥 |
| `scripts` | 5 个场景一键运行器 | 不含业务逻辑 |

## 4. 核心接口

```
ModelClient.decide(state: LoopState, observations: list[Observation]) -> ActionDecision
Tool.name: str
Tool.run(args: dict) -> ToolResult
Dispatcher.dispatch(decision: ActionDecision) -> ToolResult
Policy.validate(decision: ActionDecision, state: LoopState) -> ValidationResult   # ok | reject(reason)
Loop.run(task: TaskInput) -> RunResult
TraceWriter.emit(event: TraceEvent) -> None
```

**对外命令面（唯一入口）**：

```
python -m src.cli run --input <json> [--out <dir>] [--model real|mock] [--max-steps N]
python -m src.cli scenarios          # 跑全部 5 个场景，产出 examples/
```

**接口纪律**：模型只能产出 `ActionDecision`，**没有任何路径能让模型直接调用工具或写 state**；工具只能被 dispatcher 调用。

## 5. 关键数据结构

| 结构 | 关键字段 |
|---|---|
| `TaskInput` | topic, audience, platform, target_duration_s, style, material_ids?（可选） |
| `ActionDecision` | `decision_basis`（简短决策依据，非思维过程）, `action`, `args` |
| `ToolResult` | tool, ok, args, `digest`（回灌模型的摘要）, data?, `error_code`?, error_message? |
| `Observation` | step, action, args, result_digest, accepted |
| `Shot` | shot_id, narration, visual, subtitle, `duration_s`, `material_ids[]` |
| `ScriptDraft` | title, shots[], `estimated_total_s`, material_refs[], risks[] |
| `CheckReport` | kind(`duration`/`rules`), passed, violations[{code,msg,shot_id?}], measured |
| `LoopState` | task, draft?, observations[], steps_used, tool_calls_used, status |
| `RunResult` | `status`, script?, reason?, steps_used, trace_path |
| `TraceEvent` | step, action, args, result_digest, `decision_basis`, ts |

**动作白名单（8 个）**：`search` / `rewrite_query` / `ask_clarify` / `compose` / `estimate` / `compress` / `check_rules` / `finish`
（`estimate` 与 `check_rules` 分离，便于分别断言时长与规则两条修正线；`compress` 见 R10。）

**错误码（同时是 5 个验收场景的判定锚点）**：
`MISSING_INPUT` / `SEARCH_EMPTY` / `TOOL_ERROR` / `DURATION_EXCEEDED` / `RULE_VIOLATION` / `STEP_LIMIT` / `UNSATISFIABLE`

## 6. 主链路顺序

```
1   加载 TaskInput → 校验必填（topic/platform/target_duration_s）
2   必填缺失 → 终止 needs_input(MISSING_INPUT)                    ← 场景：缺关键信息
3   初始化 LoopState + TraceWriter
4   ┌─ 循环开始（step + 1）
5   │  model.decide(state, observations) -> ActionDecision
6   │  policy.validate：白名单 → 前置条件 → 上限 → 重复检测
7   │    └ 被驳回 → 记录 rejected observation，回灌下一轮
8   │  dispatcher.dispatch → tool.run → ToolResult
9   │  trace.emit(step, action, args, digest, decision_basis)
10  │  observation 回灌
11  │  终止判定：finish / 触顶 / UNSATISFIABLE → 退出
12  └─ 否则回到 4
13  组装 RunResult（G1 或 G2）
14  落 trace 文件至 examples/，返回退出码
```

**顺序性约束（由 policy 强制，不靠代码顺序硬编码）**：

- `finish` 前置：已执行过 `estimate` 与 `check_rules`，且最近一次均 pass；
- `estimate` / `check_rules` 前置：`LoopState` 中必须已存在 `ScriptDraft`；
- `material_ids` 为空时，`finish` 前置额外要求已执行过 `search`（B4）；
- 三重上限：`max_steps`、`max_tool_calls`、同一 `(action, args)` 重复次数上限；
- 超时长修正计数：累计 2 次后，只能 `finish(UNSATISFIABLE)`（B3）。

## 7. 权限、隔离与边界

| 边界 | 规则 |
|---|---|
| **密钥** | 只从环境变量读取；不进入代码、日志、trace、示例输出；`.env.example` 仅列变量名 |
| **网络** | 全系统唯一出网点是 `llm`；三个工具纯本地、无网络 |
| **文件写** | 仅 `trace` 与 `cli --out` 可写；工具对 `data/` 只读 |
| **模型权限** | 无副作用：不能执行工具、不能改 state、不能写文件，只能“提议动作” |
| **确定性边界** | `search` / `duration` / `rules` 必须确定且可复算；仅 `model.decide` 非确定 |
| **离线 Mock** | 与真实模型**同一条循环**，只替换 `decide()`；Mock 不证明决策质量，须在文档标注 |
| **数据** | 全合成，不含真实品牌、真实用户、隐私 |
| **上限即边界** | 触顶必须返回 `incomplete(STEP_LIMIT)`，禁止静默截断 |

## 9. 实现期修订（与本文骨架的差异，逐条说明，未静默删改）

| # | 原骨架 | 实现后 | 原因 |
|---|---|---|---|
| R1 | 动作白名单 6 个 | **7 个**，新增 `compose` | 骨架缺“写脚本”动作，`estimate` 的前置（须有 ScriptDraft）无法满足，闭环接不上 |
| R2 | `Shot` 只有 `material_ids` | 增加 `fact_refs: [{material_id, fact}]` | 只绑素材 ID 属装饰性引用；改为必须引用**素材原文事实**，编造才能被机械拦截 |
| R3 | `rules` 3 类检查 | 增至 6 类：`FORBIDDEN_PHRASE` / `MISSING_REQUIRED` / `UNSOURCED_CLAIM` / `NO_FACT_REF` / `INVALID_FACT_REF` / `FACT_REF_NOT_IN_SHOT` | 对应 R2 |
| R4 | 未规定观察内容 | **观察必须可行动**：`search` 回传 facts 正文；`rules` 回传“该素材可用事实”；`estimate` 回传“需减少 N 字 / 目标上限 N 字” | 实测：观察只说“未通过”，模型只能反复检索或象征性删两字，修正不收敛 |
| R5 | `max_fixes = 2` | **3** | 实测 near-miss（5.2s vs 5.0s）被误判为“不可能”，2 次过紧 |
| R6 | `max_steps = 8` | **16**（`max_tool_calls = 18`） | 实测一次完整修正链常需 7–11 步 |
| R7 | 无 `revision` 字段 | `LoopState.revision` | 改稿后再次 `estimate` 会被重复动作检测误杀 |
| R8 | 错误码 6 个 | 增加 `MODEL_ERROR` | 区分“模型调用失败”与“工具失败” |
| R9 | 未规定密钥防泄漏 | 新增 `.gitignore`，trace 写入前脱敏 | 项目根有明文 `.env` |
| R10 | 压缩由模型自由改写旁白 | **新增确定性工具 `compress`**，模型只决定“何时压”，裁剪算术由工具完成 | 自由改写不可复现：同一输入修正成功率实测仅约 1/6。改为工具后同一场景 3/3 收敛，且每次都落在 7.0s / 7 步 |

### 已知限制（实测，如实记录）

- **紧时长场景的修正已改为确定性**：`compress` 工具接管裁剪算术后，`02_overrun` 连续 3 次均
  `8.8s → 压缩 → 7.0s` 收敛（R10）。**残留不确定性仅剩下“模型是否会调用 compress”**，
  模型若绕过它手改旁白，仍可能不收敛。
  原因是模型每次只削 2–4 字，而目标常需削减 10 字以上。建议报告中如实记录，或重跑取成功样本。
- **欠时长不阻断**：`target_duration_s` 只作为上限校验，脚本明显偏短（如 30s 目标只写 15s）不会失败。
- **语义层编造仍有残留**：`fact_refs` 能保证“引用真实存在”，但无法机械判定“旁白是否超出所引事实”。
  已用提示词约束 + 人工抽查兜底，未做自动化语义核验。
