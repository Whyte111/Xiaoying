## 2. 硬约束（不可协商，违反即缺陷）

1. **只写草稿，不发布**。任何"已发布 / 已排期生效"的表述都是关键缺陷。
2. **不得擅自改动用户的硬性发布要求**。改时段必须降级为"建议 + 待确认"，需用户同意才成立。
3. **真 ReAct 循环**：模型选择动作 → 执行工具 → 观察结果 → 模型据此调整下一步或结束。固定条件分支、自动重试、事后补写的决策日志**不算完成**。
4. **步数 / 工具调用上限**必须存在，达上限返回明确未完成状态（不是抛异常、不是静默停止）。
5. **防重复**：相同请求重复保存只产生一份草稿。
6. **保存失败必须明确返回失败**，不得虚报成功、不得"部分成功"含糊。
7. **六项必测全覆盖**：正常排期、素材信息缺失、规则风险、时段冲突、重复提交、保存失败。
8. **模型不可用须有离线 Mock 入口并声明边界**；Mock 只证流程，不证真实决策效果。
9. **无真实密钥、无隐私数据**；`data/` 必须是合成资料。
10. **代码可运行 > 任何描述**；截图/视频不能替代代码。
11. 3 小时为**建议投入**（软），但必须记录实际用时与未完成部分（落在 `05-retrospective.md`）。

**结构与覆盖的隐含硬账**：`examples/` 只有 ≥3 组，却要覆盖 6 个验收点 → 一组用例必须复用覆盖多点，需在 `03-evaluation.md` 显式给"用例 × 验收点"矩阵，否则会被判漏测。

## 3. 隐含要求

- **工具集是既定的 4 个**：素材读取、规则检查、时段查询、排期草稿保存。决策必须真的消费工具返回，不能由模型先编结论再补调用。
- **"待确认"是有独立状态的对象**，不可与"已确认/已保存/已排期"混用；参考实例明确要求"建议 19:00 并标记待确认"。
- **信息缺失时不得幻觉补全**：应停在"补查 / 请求确认"，而不是猜元数据。
- **判重粒度未定义**（【待确认】：按素材 ID？按"素材+建议时段"？按请求指纹？）——这是实现前必须定的一件事，直接影响"重复提交只产生一份草稿"是否成立。
- **工具失败要可复现**：保存失败场景需可控注入，并说明是 Mock 故障点。
- **"时段冲突"需真实判定**：已有排期与建议时段的重叠/边界（如 18:00 已占用 → 19:00 可用），含跨天、区间重叠语义；时区口径未定义（【待确认】：是否固定单一本地时区）。
- **Trace 是评分主体**：字段齐全、与 `examples/` 实际输出一致，`03-evaluation.md` 要引用具体文件路径。
- **可解释取舍**：用不用框架不加分；要写清为什么这么选、改了什么结果（`02-solution.md`）。
- **评审可跑通**：无密钥、离线、一条命令起步。
- 【推断】仓库目录/文档组织宜对齐参考示例 `lwz1357/agent-campus-submission-example`（我**未**查看该仓库，仅为格式参照，不作内容依据）。

## 4. 什么叫完成

以"评审能独立复现并逐条勾选"为准：

- [ ] 干净环境按 README 命令可安装、可启动、可跑测试，测试全绿。
- [ ] 无 API Key 时用 Mock 入口同样能跑出完整演示（边界已在文档声明）。
- [ ] 6 个验收点每个都有对应 Trace 文件，`03-evaluation.md` 有引用矩阵，无遗漏。
- [ ] ≥2 条执行路径能看出"工具结果不同 → 下一步不同"的因果，而不是两条脚本。
- [ ] 重复提交同一请求：第二次返回既有草稿/幂等命中，仓库内只存在一份草稿（有证据）。
- [ ] 保存失败：明确返回失败状态，且草稿未被写成"成功"（有证据）。
- [ ] 触发上限：返回明确"未完成"状态（有证据）。
- [ ] 全程无"已发布"字样与真实发布调用。
- [ ] 文档五件套齐备，含实际用时、失败案例与已知限制。
- [ ] 已提交题号、GitHub URL、最终 commit SHA。

## 5. 最容易翻车的风险点

按"扣分严重度 × 发生概率"排序：

1. **假 ReAct**（最致命）：把流程写成 if/else 或把决策依据写成事后叙述，模型并未真正读工具返回。评审一眼可辨。
2. **越权/虚报**：把"建议时段"说成"已排期"，或第二份草稿被静默覆盖后仍报成功。
3. **静默改硬性要求**：用户要 18:00，模型直接给 19:00 且不标"待确认"。
4. **幂等假象**：仅进程内内存去重（重启/新请求就重复）、或判重键过粗把不同素材合并、过细则同请求产生两条。
5. **失败被吞**：`try/catch` 后仍返回成功，或只报"部分成功"。
6. **信息缺失时幻觉补全**：省掉"请求确认"环节。
7. **上限形同虚设**：无上限、或达上限抛异常/直接静默退出。
8. **冲突判定边界错**：只比字符串不等、不判区间重叠、忽略跨天/时区。
9. **文档与证据不一致**：`03-evaluation.md` 写的结果和 `examples/` 实际输出对不上（评审会交叉核对）。
10. **评审跑不起来**：依赖未锁版本、必须真实 key、Mock 入口未接线。
11. **3 小时内的范围失控**：做 UI / 多 Agent / 部署 / 真发布对接，导致核心链路（冲突调整、确认边界、防重复）不完整。原文已声明这些非必需。
