# 05 复盘

## 最难的问题

### 1. "真 ReAct" 与 "预设流程" 的界线

门控把动作空间收窄后，很多步骤只剩一个可选动作，模型没有选择余地，看起来就像固定流程。
题面允许"预设流程作执行骨架"，但"仅有固定分支"不算完成。

处理方式：保留骨架，把**分岔点**留给模型——冲突后换不换时段、warn 后先确认还是直接保存。
`examples/m01-llm.json` 与 `examples/m03-llm.json` 展示了模型在同一套骨架上走了两条不同路径。
这也是本方案最容易被质疑的地方，所以证据放在最显眼处。

### 2. 判重粒度

"素材 ID + 时段"看着更精确，但会导出一素材多草稿，与输出字段"建议时段"的单值语义打架。
最终选素材 ID 唯一 + 指纹判断是否需要更新，代价是同素材的多个候选时段不能并列保存。

### 3. 失败语义比功能更难

三种"看起来正常、结论却是错的"状态，都是复查阶段才发现的：

- 工具挂了 → 空转到上限，报"未完成"
- 模型提前结束 → 报"草稿保存失败"
- 写盘失败 → 内存里留着没落盘的草稿

它们的共同点是：**程序没崩，但对外说的话是假**。这类问题测试不会自己冒出来，只能靠逐个场景构造。

## 学到了什么

- 状态语义要穷举：`FAILED` 与 `INCOMPLETE` 混用，等于对用户撒谎。
- 证据必须与代码同版本：trace 一开始是覆盖写，重跑一次就把"首次创建"的证据冲掉了。
- Mock 只能证明流程，不能证明决策质量；两条真模型 trace 比十条 Mock 有用。
