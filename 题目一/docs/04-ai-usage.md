# 04 AI 使用说明

## 分工

| 角色 | 做了什么 |
|---|---|
| 人 | 定方向与边界：选"确定性内核 + 受限模型决策"、运行形态用 CLI、判重按素材 ID、单时区不跨天；提供模型 key；每次改动后亲自跑命令确认 |
| AI | 需求梳理、系统骨架、全部代码、全部测试、审查与修复、本文档 |

## AI 产出中被推翻或修正的部分

这些不是"AI 一次做对"，而是评审式复查后改掉的：

| 原方案 | 问题 | 结论 |
|---|---|---|
| 保存失败最多重试 1 次 | 与"自动重试不算决策"冲突；实测第一次失败第二次成功，会对外报成功 | 改为单次尝试，失败即 `FAILED` |
| `Facts` 只有 5 个字段 | 无法表达"是否完整/是否查过冲突/是否已问过" | 扩到 18 个字段 |
| 工具签名 `read_material(id)` | 无法注入数据源，不可测 | 改为 `Toolbox` 上的方法 |
| 判重键"素材 ID + 时段" | 会导出一素材多草稿，与"每项素材一个建议时段"矛盾 | 改为素材 ID 唯一 + 指纹 |
| 工具故障、模型提前结束 | 分别被报成 `LIMIT_REACHED` 和"保存失败" | 新增 `TOOL_FAILED` / `INCOMPLETE` |

## 怎么验证 AI 的产出

1. **单元/集成**：52 项 `unittest`，覆盖六项必验与主要异常路径。
2. **探针**：对可疑点单独写一次性脚本实测行为（而非相信代码注释），发现并修复了输入崩溃、写盘脏内存、越权建草稿等问题；探针脚本已删除，结论固化进 `tests/test_robustness.py`。
3. **真实 CLI**：`examples/` 下 10 组产物全部由当前代码实跑生成，非手写。
4. **真模型**：`--provider llm` 跑两条路径，`decision_degraded=false`，确认没有回退到策略。

## 未使用 AI 的地方

- 没有让 AI 直接"生成一份看起来能跑的产物"：所有 trace 都由 CLI 实际执行产生。
- 模型只用于决策，不参与写文件、不接触密钥；密钥仅从环境变量读取。
