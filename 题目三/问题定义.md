# 企业知识问答 Agent — 可执行问题定义

> 依据：`需知.txt`、`题目三.txt`。本文只定义问题，不含方案与代码。
> 标记说明：`❓` = 原文未规定、我不做假设，需你确认。

---

## 1. 最终交付物

**一个可被评审在本地跑起来的仓库**（单一仓库，公开或对指定评审账号可读），提交「题号 + GitHub URL + 最终 commit SHA」。

仓库必含：

| 项 | 内容 |
|---|---|
| `README.md` | 环境、安装、运行命令、评审入口 |
| `src/` | 代码与模型/工具接入 |
| `tests/` | 可执行测试 |
| `examples/` | ≥3 组输入、实际输出、Trace |
| `data/` | 合成 FAQ / 制度（每条含文档 ID、版本日期） |
| `docs/01~05` | 需求 / 方案与取舍 / 评估 / AI 使用 / 复盘 |
| 依赖文件 | `requirements.txt` 或 `package.json` |
| `.env.example` | 所需变量；无则注明"无需配置" |

运行方式**三选一**：CLI / HTTP API / Notebook，并给出可复制的运行命令或执行步骤。

**Agent 自身每次必须产出的四件套**：回答正文 / 引用（文档 ID + 原文片段）/ 资料缺口 / 任务状态。

**Trace 必须含**：步骤、工具参数、返回摘要、后续动作、简要决策依据（不含模型内部思维过程）。

❓ 范围待确认：本轮只要本地仓库，还是必须先推到 GitHub 并给出 SHA？题号是多少？截止时间？

## 2. 硬约束

不满足即判不达标，不是加分项：

1. **真 ReAct 循环**：必须是「模型选动作 → 执行工具 → 观察结果 → 模型决定下一步或结束」。固定条件分支、自动重试、预设决策日志**均不算**。
2. **≥2 条执行路径的记录**，且两条路径的差异必须来自工具返回结果（模型据此改变动作），不能用两个不同问题凑数。
3. **必须有步数 / 工具调用上限**，触顶返回明确的"未完成"状态。
4. **冲突不擅自裁决**：资料冲突时列出冲突与引用、请求确认适用制度；不能只挑一个答案。
5. **引用可核验**：片段逐字来自原文且能支撑结论。错误引用属关键缺陷。
6. **六个验收场景全绿**：明确答案 / 文档冲突 / 资料外问题 / 改写后的相似问题 / 上下文追问 / 工具失败。
7. **证据覆盖**：≥3 组输入覆盖「正常、资料不足、工具失败」三类，并覆盖全部验收点（一组可覆盖多点）；Trace 与测试结果存 `examples/`，`docs/03` 引用对应文件。
8. **可运行性**：截图/视频不能替代代码；无密钥时必须提供离线 Mock 入口并写明边界（Mock 只验流程，不证明真实决策效果）。
9. **合规**：不提交真实密钥与隐私数据；数据必须是合成的。
10. **用框架须注明**：版本、使用的功能、框架承担的职责。框架名称不加分。
11. **预算**：建议 3 小时（❓硬性还是指导），优先核心链路，记录实际用时与未完成部分。UI、线上部署、多 Agent、生产级 Runtime 均非必需。

❓ 边界待确认（以下我不做假设）：
- 模型 / 密钥 / 网络是否可用？用哪家模型？
- 语料自带还是我造？文档数量与冲突设计由谁定？
- 运行方式三选一选哪个？语言 / 框架有无偏好或限制？
- 评审环境（OS、Python / Node 版本）？
- "两条执行路径"的判定口径：两个问题，还是同一问题下的两种动作序列？

## 3. 隐含要求

原文没写、但评审一定会查：

1. **数据驱动，不能把答案写死**。审核要点明说「替换文档内容，核对答案与动作是否改变」——答案或引用片段一旦硬编码，换文档即崩。
2. **检索质量是主战场**。高分依据是「检索改进 + 冲突处理」。必须同时召回 D01 与 D02 才可能发现冲突；只召回一条就会得出"无冲突"的错误结论。
3. **改写鲁棒**：同义、省略式提问要能命中同一批文档（需要查询改写或归一化）。
4. **多轮要真用上历史**：追问（"那差旅呢""这个呢"）必须做指代消解，否则第二轮检索为空。
5. **拒答优于编造**：资料外问题要明确"查不到"，而不是给一个像样的答案。
6. **失败要可见**：工具异常必须反映到状态与回答里，不能崩、不能静默重试到死、不能吞错硬答。
7. **引用是可复核的工程问题**：切分/清洗后偏移错位会让片段与原文对不上，需要校验。
8. **测试要能自动跑**：`tests/` 是可执行断言，不是手工记录。
9. **文档要说真话**：已知限制、失败案例、AI 生成 vs 我修改的部分都要写——`docs/04`、`05` 在考察"主动学习与改进"。
10. **时间与取舍要留痕**：3 小时下评审看的是"砍得对不对"，不是"做得多"。
11. ❓ 文档带版本日期，是否意味着"取最新版"？题目**未给优先级规则**，不能默认最新优先，只能作为冲突线索呈现。

## 4. 什么叫完成

逐条可勾即完成：

- [ ] 评审 clone 后按 `README` 能在 5 分钟内跑通，无需口头补充。
- [ ] 无密钥时走离线 Mock 也能完整演示全流程，边界已写明。
- [ ] 六个验收场景各有一份真实 Trace + 实际输出，`examples/` 可查，`docs/03` 有引用。
- [ ] ≥2 条执行路径，能指出"因为工具返回了 X，模型下一步改成了 Y"。
- [ ] 冲突场景：同时列出 D01/D02 与原文，状态为"需澄清"，未擅自给单一答案。
- [ ] 资料外 / 资料不足：明确说缺什么，不给无依据答案。
- [ ] 工具失败：有明确失败状态与降级路径，进程不崩。
- [ ] 触顶：返回"未完成"而非半截答案。
- [ ] 每条回答的引用片段能在 `data/` 原文中逐字找到。
- [ ] 替换 / 删改 `data/` 任一文档后重跑，答案与动作随之变化（证明非硬编码）。
- [ ] `tests/` 全绿且可复现。
- [ ] `docs` 01–05 齐全，含实际用时、未完成部分、AI 使用边界。
- [ ] 已提交题号 + 仓库 URL + commit SHA，评审账号可读。

## 5. 最容易翻车的风险点

按「致命度 × 概率」排序：

1. **假 ReAct（最高危）**：实际是 if/else 流水线，模型只负责最后写答案。原文明确"不视为完成 ReAct 决策要求"。
2. **演示用硬编码**：把 D01/D02 的答案、片段、结论写死以通过 demo。替换文档即暴露，且踩"无依据回答/错误引用"红线。
3. **冲突被静默消解**：模型"聪明地"选了 30 天或 15 天；或只召回一条就宣布无冲突——正是参考实例明令禁止的。
4. **引用对不上原文**：切片偏移、二次改写、用摘要冒充原文，导致片段无法逐字核验。
5. **多轮失效**：第二轮不做指代消解，检索不到，退化成"资料不足"。
6. **工具失败处理成三种坏形态之一**：崩溃 / 无限重试 / 吞错硬答。
7. **三小时失控**：时间花在框架、UI、部署上，核心循环与证据材料没做完。
8. **上限缺失或触顶无状态**：跑飞、烧 token、结果不可解释。
9. **材料不自洽**：Trace 手写、测试跑不过、缺 `.env.example`、缺 SHA、私有库评审进不去。
10. **评审环境无密钥且无 Mock**：跑不起来，等于零分。
11. **Trace 越界**：写了模型思维过程（不必要且有风险），却漏了"工具参数 / 决策依据"。

**Top 3 是 1、2、3**——分别对应"不视为完成 ReAct""关键缺陷""参考实例明令禁止"。
