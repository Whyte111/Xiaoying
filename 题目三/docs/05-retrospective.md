# 05 复盘

## 最难的问题

**怎么证明"模型确实在决策"，而不是代码写死了一条流程。**

这件事没有自证的写法。最后的做法是把它变成可观察的：循环只有一份，工具返回值原样回灌给模型，轨迹里能看到"因为上一次返回了 X，下一步改成了 Y"。
比如检索故障那次，模型先是换关键词重试，结果太宽泛，又自己收窄了一次才作答。这种链在预设流程里写不出来，也难以伪造。

**第二难的是"不信任自己"。**
实现完成后连做三轮自检，三轮都翻出了问题，其中两个是修复本身引入的。教训很直接：这类系统里，任何一个启发式规则的修正都会带来新的边界，必须同时补一条反例测试，否则就是按下葫芦浮起瓢。

## 学到什么

1. **约束要落在代码里，不能落在提示词里。**
"请不要编造"写在 prompt 里只是建议；写进 `assemble()` 才是保证。所有关键判定（冲突、引用、状态）最终都做成了代码分支，并配了单测。
2. **启发式需要标定，不能凭感觉。**
冲突阈值不是拍脑袋定的，是先打印出所有文档对的重叠度（真冲突 0.36、最大非冲突 0.22），再取中间值。没有这步，"0.3"和"0.7"没区别。
3. **离线可复现比在线效果更重要。**
评审能 clone 就跑、跑完结果一致，比多回答对两个问题更有价值。这也是坚持零第三方依赖、坚持 FakeLLM 共用同一循环的原因。

## 如果继续做

1. **重复性验证**：同一问题连跑 5 次统计状态一致性，补上现在 n=1 的证据空缺。
2. **网络异常补测**：超时与 4xx/5xx，目前只测了连接被拒。
3. **提示注入实测**：构造含"忽略以上规则"的文档，验证包裹策略是否真的生效。
4. **语料扩容后的阈值重标定**：语料从 3 篇扩到几十篇，0.30 这个值大概率要动。
5. **会话持久化**：目前只保留最近 2 轮且不落盘，长对话会退化。

## 一句话总结

这套系统的正确性不来自"模型很聪明"，而来自"模型出错时有人兜着"——兜底是代码，不是提示词。
