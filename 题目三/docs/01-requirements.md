# 01 需求

## 用户与目标

公司员工遇到制度类问题时，能拿到**有出处**的答案，而不是一段看似合理的猜测。
系统对每个问题必须给出：回答、引用（文档 ID + 原文片段）、资料缺口、任务状态。

## 输入与材料

- 输入：一个问题；可选对话历史。
- 材料：`data/` 下带 `doc_id` 与 `version_date` 的合成制度文档（3 篇）。
- 工具：检索片段、读取原文。

## 交付形态

CLI。一条命令一个问题；传多个问题即多轮。
输出为纯文本四件套 + 可选 JSONL 轨迹。

## 范围

做：检索 → 决策 → 回答的完整链路，含冲突、资料不足、工具失败、多轮、步数上限。
不做：界面、线上部署、多 Agent、生产级 Runtime、鉴权、持久化存储。

## 成功标准

1. 六类问题都能得到**状态正确**的响应：
   明确答案 / 文档冲突 / 资料外 / 改写后的相似问题 / 上下文追问 / 工具失败。
2. 每个 `ANSWERED` 的引用都能在原文中逐字找到，且与回答相关。
3. 文档冲突时必须列出双方并要求确认，不擅自选一个。
4. 修改 `data/` 中的内容，答案随之改变（证明不是硬编码）。
5. 无密钥、无网络时仍能完整运行并复现结果。
6. 单轮步数有上限，触顶返回明确的未完成状态。
