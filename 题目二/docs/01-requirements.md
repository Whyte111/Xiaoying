# 01 需求与范围

## 用户与目标

运营人员要在**预算与截止时间**内产出一份内容活动方案。系统需要给出：任务计划、每步状态、工具结果、费用合计，以及已保存方案或未完成原因。

## 输入

| 输入 | 说明 | 校验 |
|---|---|---|
| 主题 | 内容方向，决定检索关键词 | 必填、≤2000 字符 |
| 预算 | 模拟单位 | 必填、有限正数 |
| 截止时间 | ISO 日期或日期时间 | 必填、可解析 |

场景数据（`data/scenario.json`）：素材库、工具费用与耗时表、备选方案 A（12）/ B（8）。

## 范围

**做**：单机 CLI；4 个工具；预算约束下的动态重规划；失败降级与续跑；幂等；trace。

**不做**：Web 界面、部署、多 Agent、生产级 Runtime、真实排期。

## 成功标准（验收点）

| 验收点 | 判定 | 用例 |
|---|---|---|
| 正常完成 | 4 步成功、产物落盘、费用自洽 | `examples/case1-normal` |
| 缺预算 | 阻断，0 次工具调用 | `tests/test_hardening.py` |
| 缺截止时间 | 阻断，0 次工具调用 | `examples/case5-missing-deadline` |
| 工具失败 | 降级后完成，失败记录保留 | `examples/case3-tool-failure` |
| 预算超限 | 改选替代方案；仍不可行则返回缺口 | `examples/case1` / `case2` |
| 重复执行 | 复用结果，不重复调用/保存 | `examples/case4-repeat` |

加分项：失败续跑（`examples/case8-resume`）、工具超时、`skipped` 状态。

## 已知边界

- 截止时间只做必填与格式校验，**不做时间可行性核算**（缺少“可用工时”输入，不编造）。结果中 `time_checked=false` 明示。
- 默认离线规则决策器；真实模型需配置 Key。
