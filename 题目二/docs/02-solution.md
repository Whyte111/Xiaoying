# 02 设计说明

## 一句话

把「决策」和「执行」彻底分开：引擎只会 `决策器.next(观察) -> 动作`，工具只做纯函数，约束由一个地方统一算，状态落在磁盘上。

## 模块

| 模块 | 职责 | 不负责 |
|---|---|---|
| `cli` | 参数、模式选择、渲染、退出码 | 业务逻辑 |
| `engine` | 循环、上下限、状态回写、trace、结果组装 | 不做预算判断 |
| `decision` | `MockPolicy`（规则）/ `LLMDecisionPolicy`（模型） | 不改状态 |
| `guards` | 输入、预算、依赖、时间四类校验，只产出 `Violation` | 不修复、不决策 |
| `tools` | 4 个工具，统一返回 `ToolResult` | 不决策 |
| `state` | 指纹、幂等记录、续跑快照 | 不调工具 |
| `store` | 读场景数据并校验结构 | 不解释业务 |
| `llm` | OpenAI 兼容调用、输出解析、失败降级 | 不碰业务状态 |

## 主链路

```
解析参数 → 校验输入 → 计算指纹 → 查幂等记录
  ├─ 已完成 → 直接复用，0 次调用
  └─ 有快照 → 继承已成功步骤，续跑
→ 循环 {
     算约束(预算/依赖/时间) → 决策器出动作
     → 校验动作(未知动作/无产物 finish) → 执行工具
     → 回写状态 → 落盘快照 → 记 trace
   }
→ 汇总费用 → 未跑的步骤标 skipped → 写结果与 trace
```

## 关键设计决定

**1. 原生实现，不用 Agent 框架**
框架不加分，却带来安装、版本、调试三重成本。主循环约 150 行，出问题能直接定位。

**2. 决策器是接口，默认 Mock**
`MockPolicy` 完全离线、确定性，评审零配置可跑；`LLMDecisionPolicy` 同接口挂在同一循环上。模型不可用时降级到 Mock，trace 逐轮记录 `source`，结果里汇总 `fallback_calls`，不冒充模型决策。

**3. 预算只在一个地方算**
`guards.check_budget(spent, estimate, budget, save_fee, saved)` 是唯一口径：未保存时把保存费算进去，已保存时不再重复计入。决策器只读 `Violation` 决定换方案还是停，不自己算钱——避免两处算法漂移。

**4. 指纹 = 输入 + 决策来源 + 场景数据哈希**
换 provider 或改 `data/scenario.json` 都视为新任务，避免用旧结果冒充新结论。

**5. 续跑继承结果，但不继承重试计数**
否则一次环境故障把重试次数耗光，任务会被永久锁死。

**6. finish 必须有产物**
引擎拒绝“模型声称完成但没保存”的情况，防止空结果被判成功。

**7. 有副作用的工具超时不算普通失败**
`save_plan` 超时返回 `OUTCOME_UNKNOWN` 并立即停止，避免重复保存或幽灵产物。同步函数无法抢占式中断，这是已知局限。

## 数据结构

`TaskInput` → `Observation`（决策器唯一可见）→ `Action` → `ToolResult` → `FinalResult`。
`Observation` 只携带事实（素材、脚本、估算、已花费、违规、上一步结果），不含轮次依赖，决策器无法靠“第几步”作弊。

## 扩展点

- 加工具：在 `tools` 实现 `_<name>`，`decision` 的工具清单同步
- 加方案：改 `data/scenario.json` 的 `plan_options`
- 换模型：实现 `DecisionPolicy` 并接到 `cli`
